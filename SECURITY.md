# Безпека Ord 2

## Головне: де лежать ключі API
- У репозиторії й на сайті **немає жодного ключа API**. Це статичний сайт: серверного коду, який міг би зберігати чужі ключі, тут немає.
- Кожен користувач вводить **власні** ключі в Налаштуваннях. Вони зберігаються лише в його браузері: зашифровані паролем (AES-GCM 256, ключ із пароля через PBKDF2-SHA256, 310 000 ітерацій) у `localStorage`, або в `sessionStorage` до закриття вкладки. Відкритого тексту на диску немає.
- Ключі не потрапляють у стан застосунку, експорт JSON, хмарну синхронізацію, Firestore чи спільний контент. Запити до ШІ йдуть напряму з браузера до провайдера (`fetch` з `referrerPolicy: no-referrer`, без cookies).
- Не вписуй ключі в `js/firebase-config.js`, у код, у README чи в issue. Це публічний репозиторій.

## Обмеження, які треба розуміти
- Усі сторінки на `vasyl-www.github.io` ділять один origin і один `localStorage`. Тому ключі лише зашифровані; не залишай їх відкритим текстом ніде.
- Захист паролем не врятує від шкідливого розширення браузера чи шкідливого коду на цьому ж origin, поки сховище розблоковане. Ставь у кабінеті провайдера **ліміт витрат** і, де є, обмеження прав ключа. Для безкоштовних ключів ризик менший.
- Content-Security-Policy (у `index.html`) дозволяє скрипти лише з цього сайту та `apis.google.com` (потрібно для входу через Google) і запити лише до перелічених API. Не додавай сторонні скрипти й CDN.
- Контент спільноти вважається недовіреним: текст екранується, SVG чиститься й показується лише як картинка, посилання на відео будуються лише як пошук YouTube.

## Firebase
- `apiKey`, `projectId`, `appId` у `js/firebase-config.js` не секретні. Доступ обмежують `firestore.rules` і список дозволених доменів в Authentication. Не публікуй сервісні акаунти.
- Рекомендовано: Authentication → Settings → Authorized domains: лише `vasyl-www.github.io` і `localhost` для розробки. У Google Cloud Console обмеж API key за HTTP-реферером `https://vasyl-www.github.io/*`. Увімкни Firebase App Check (reCAPTCHA) проти зловживань квотою.
- Модерація: скарги пишуться в колекцію `reports`, читати їх можна лише в консолі Firebase. Видаляти чужі записи можна там само.
